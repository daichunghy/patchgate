# G3 contract decisions

**Date:** 2026-08-13  
**Scope:** Prompt 4, authenticated GitHub adapter  
**Authority:** `PROJECT_CONSTITUTION.md`, `AGENTS.md`, current schemas and evaluator

## Decision 1: preserve the current scalar pull-request contract

The current `EvaluationInput` stores one repository owner/name and one pull-request
number. It does not store immutable repository ID, pull-request ID, event identity,
authenticated merge-group membership, or a provenance envelope. A schema extension
would require a new input/receipt namespace and migration of every existing fixture.

G3 therefore keeps the existing wire contract for backward compatibility and binds
the richer identity in the adapter's immutable `SnapshotIdentity` and provenance
digest. The builder rejects a merge-group request because it cannot safely project
authenticated multi-PR membership into the scalar contract. This is an explicit
fail-closed limitation, not merge-queue support.

## Decision 2: native controls are normalized but not compiled into PatchGate rules

The current evaluator can create requirements from `PatchgatePolicy`; a
`PolicySource(kind: ruleset|branch_protection)` alone does not create a native
requirement. The adapter therefore normalizes applicable rulesets and branch
protection and rejects a snapshot when an active decision-bearing native control
cannot be represented by the current evaluator. Empty, complete native-control
observations are allowed. The adapter never translates native controls into a
synthetic `patchgate.yml` rule.

## Decision 3: cache is deferred

Persistent caching is not needed to prove the first vertical slice and would add
authorization, privacy, and 304-body identity risk. G3 sends no conditional headers,
persists no response body, and rejects an unexpected 304 without a validated cache
body. PG-315 is `evaluated_deferred`.

## Consequences

The local/mock adapter can build and validate complete `pull_request` head/merge
snapshots, including exact-base policy, changed paths, native linked issues,
checks/workflows, reviews, qualification, CODEOWNERS, budgets, redaction and
TOCTOU revalidation. The G3 overall gate remains open until an explicitly
authorized live read-only smoke supplies current API/permission evidence.

### 2026-08-20 superseding implementation note

The original decision remains authoritative for merge-group membership and
unsupported Ruleset semantics, but branch protection and a Rulesets subset now
have a versioned contract. Required status checks, required approvals and
applicable CODEOWNERS gates are represented in `EvaluationInput.nativeControls`,
bound to the base-revision policy source digest, and covered by fixture and
live-smoke evidence. `require_last_push_approval`, review-thread resolution and
other unsupported rule semantics remain evidence-missing until their evidence
is added. The initial live rejection and the follow-up complete but non-ready
snapshot are recorded in
`docs/reviews/2026-08-20-g3-live-smoke.md`.
