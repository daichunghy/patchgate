## Findings

### P1 — G0 release and program evidence remain open

Evidence: the public repository, protected default branch and [successful
default-branch CI run](https://github.com/daichunghy/patchgate/actions/runs/32333914059),
public Project #1, four Discussions, four open contribution/pilot issues and
draft PR #9 are observable. `package.json` remains private; there is no release,
merged PR, downstream usage or completed pilot evidence.

Impact: the repository can truthfully be described as a public pre-release
open-source project, but not as a released or adopted product and not as an
eligible/selected Codex for Open Source project. The application dossier must
remain preparation-only.

Required evidence: maintainer role confirmation, working public
support/security routes, a release/rollback decision, and later usage or pilot
evidence.

### P2 — community activity is supporting evidence, not adoption

The public Project, poll-style Discussion, issue start paths and four
context-specific outbound questions show organized maintenance and ecosystem
research. They do not show independent community participation because no
external reply, contribution or pilot has been recorded yet. Keep these links
in the dossier as maintenance context, not as usage metrics.

### P1 — G4 is local candidate evidence, not shadow completion

The Action bundle now starts in a clean room without source schemas or
`node_modules`; check delivery updates an existing check by `head_sha` and
`check_name`; the consumer fixture verifies a full-SHA reference and clean-room
bundle; and `merge_group` returns explicit `evidence_missing` rather than
silently passing. These are local/fixture controls only.

Missing: a live external consumer repository, fork E2E, live merge-group E2E,
two consenting non-blocking shadow installations, public immutable Action tag
and maintainer review of observed distribution/noise.

### P2 — G3 live snapshot is complete but non-ready

The follow-up authorized smoke against public `daichunghy/patchgate#9` at PR
head `2a28e82` built a schema-valid `EvaluationInput` and
`ContributionReceipt` from 24 bounded GET requests (695088 bytes). It retained
the real missing approval/ownership/linkage evidence and returned
`human_review_required`; it did not create a check, comment, artifact or other
write. Branch-protection required checks, approval gates and the supported
Rulesets subset are now represented, and the GraphQL linked-issue observation
is complete. Unsupported Ruleset semantics, merge-group membership and
immutable last-pusher/review-thread semantics remain unsupported.
See the [G3 live smoke record](2026-08-20-g3-live-smoke.md).

### P2 — local release hardening is not yet public evidence

The current working tree contains root `action.yml`, the CodeQL workflow,
Dependabot configuration, corrected owner/contact links and expanded workflow
pin checks. `origin/main@a3745f6` still contains `.github/action.yml` and does
not contain these pending files, so they are not public evidence. After review
and publication, CodeQL and the Security Audit workflow still need successful
public runs.

## Improvements implemented in this continuation

- Added `@vercel/ncc` Action bundling with schema data embedded in the bundle.
- Added `bundle:action`, full `npm audit` coverage and bundle verification to
  the authoritative `npm run verify` chain.
- Pinned third-party `checkout` and `setup-node` workflow Actions to immutable
  commit SHAs and added a workflow-pin verification gate.
- Added clean-room startup verification for the Action bundle.
- Replaced duplicate-prone check creation with lookup plus update/create logic.
- Made `fail-on: never` non-blocking for snapshot rejection while preserving
  failure for invalid runtime configuration.
- Changed live-smoke accounting so rejected snapshots are reported separately
  and cannot be counted as passing complete snapshots.
- Used safe multiline delimiters for `GITHUB_OUTPUT` and constrained receipt
  paths to `GITHUB_WORKSPACE`.
- Added explicit non-ready handling for `merge_group` and included
  `merge_group: checks_requested` in the shadow workflow.
- Added `merge_group: checks_requested` triggers to the required CI and CodeQL
  workflows, plus a verifier that protects those triggers from regression; the
  evaluator still rejects merge-group membership until the multi-PR contract
  exists.
- Removed the implicit public GitHub badge/action-release claim from README.
- Guarded live smoke against default repositories; it now requires an explicit
  target and `PATCHGATE_LIVE_SMOKE_AUTHORIZED=yes`.
- Fixed the live-smoke schema registry so the policy schema is loaded before
  compiling evaluation/receipt schemas; the no-target guard now reaches its
  intended authorization boundary without any API call.
- Applied GitHub repository hardening: topics, Discussions, private vulnerability
  reporting, Dependabot security updates and CI-only protection for `main`;
  PatchGate remains non-required.
- Posted a public [Show and tell discussion](https://github.com/daichunghy/patchgate/discussions/1)
  asking maintainers to challenge the product boundary and review-readiness
  evidence model; no response or adoption is claimed yet.
- Added a requirements Q&A, a base-revision design note and a labeled [pilot
  request](https://github.com/daichunghy/patchgate/issues/4); these are outreach
  surfaces, not evidence of external usage.
- Added three scoped contribution issues for consumer E2E, CODEOWNERS
  conformance and release/rollback documentation; open issues are invitations
  to contribute, not evidence of completed adoption.
- Prepared root Action metadata and CodeQL/Dependabot automation in the local
  working tree; these changes remain unpublished and are not evidence of a
  release or clean consumer installation.
- Updated the dossier, threat model, support links and pre-release security
  wording to match current evidence.
- Added a versioned native branch-protection contract for required checks,
  approvals and applicable CODEOWNERS gates, with digest binding and tamper
  tests.
- Added a versioned Rulesets subset for `required_status_checks` and
  `pull_request` review parameters, with unsupported rule semantics rejected
  fail-closed and receipt-level rule gates.
- Fixed two live GitHub API compatibility gaps: `.github/patchgate.yml` base
  policy lookup and direct `Issue` nodes in `closingIssuesReferences`.
- Fixed check evidence identity so multiple jobs from one workflow run remain
  distinct instead of producing a false duplicate-workflow diagnostic.
- Fixed the GraphQL `operationName` casing so the live linked-issue query is
  accepted by GitHub instead of being rejected as an unknown operation.
- Replaced the Discussion scheduler's PAT dependency with the repository-scoped
  built-in `GITHUB_TOKEN` and added `check:community-schedule` to `npm run verify`
  for token, duplicate-title, copy-quality and two-day-cadence checks.

has prepared a dossier but has not submitted an application.
